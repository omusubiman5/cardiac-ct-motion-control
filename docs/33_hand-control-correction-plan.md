## 1. 修正の目的と原文

本人の報告・指示を起点に、Cを仮配置して切れ目の向きを調整する操作を、説明や窓の切替に頼らず確認できるようにする。修正対象を画像認識だけに限定しない。

| 本人原文 | この計画に結び付ける要求 |
|---|---|
| 「１本から２本が反応しない」 | 照準→仮配置の成立・拒否・既存仮Cを画面で区別する |
| 「マジで説明が悪い」「学習能力ないんか」 | 現在状態・選ぶ行・次の動作・成功表示を対応させる |
| 「見える」 | 仮Cが本人の画面で視認された事実を保持し、勝手に取消・再配置しない |
| 「Cの向きなのに縦回転させてどうすんねん」「縦回転しかしないぞ」 | 開口方向の面内回転と面の傾きを明確に分離し、実手の症状解消を検収する |
| 「グーが親指と認識される」 | グー／親指／つまみの混同を是正し、不明なら無作用にする |
| 「こちらでSlicerを前面に戻しました？…UI改善がUXに繋がる」 | 受付・選択・カメラ確認・サイズ設定を既存の単一Slicerドックで完結させる |
| 「お前がハンドジェスチャーのイラストを作ってテストしろよ」「やれや」 | 合成画像による自己検証から実Slicerまで実行し、実手試験と区別する |
| 「修正計画書MDを作成してください」 | 実装単位・順序・検証・完了条件を本書に記載する。今回の成果物は計画書 |

要求の根拠は[システム要求](03_system-requirements.md)のFR-008/009/010/013、OP-006/007、AC-002/011、SR-001/006。OP-006はアンカーを固定した配置面内の開口回転、OP-007は別モードでの面の傾き。縦回転の報告を理由に配置面や世界座標を勝手に置き換えない。本人指定の直径10mm・変更可能なマウスサイズ設定も維持する。

## 3. 画面と操作の修正仕様

単一ドックを維持し、常時「受付状態」「現在の操作」「仮C状態」「次の動作」「拒否理由」を表示する。選択候補と現在有効なモードを同じ表示として扱わない。

| 状態 | 大きく表示する見出し | 操作案内・結果 |
|---|---|---|
| 停止 | 操作停止中 | 開いた片手1.5秒で開始。停止理由も表示 |
| 開始直後 | 受付中・操作準備 | 一度手を下げる。まだC／視点を動かさない |
| 照準・仮Cなし | Cを置く場所を選ぶ | 1本指で照準。表面が有効なら2本指で仮配置 |
| 仮配置済み | 仮Cあり・未確定 | 2本指では追加配置しない。親指でC編集を開く |
| 編集メニュー開 | C編集・選択待ち | 青い▶の項目が候補。2本指で次、3本指で選択。連続移動は停止 |
| rotate選択成功 | Cの開口方向を調整中 | 手を左右へ。切れ目を面内で回す。中心・面は保持 |
| tilt選択成功 | Cの面の傾きを調整中 | 手を上下へ。開口回転とは別。開口方向へ戻る手順を示す |
| 凍結 | 仮C凍結・編集停止 | 再接続だけで再開しない。受付開始と明示した編集再開が必要 |
| 確認 | C確定の確認 | 対象版・直径・方向を表示。一度手を下げた独立入力で確定 |

メニュー閉後も現在モード名を残す。モード選択はサーバーの成功応答後に表示を切り替える。拒否時は前のモードを保持し、理由と回復操作を表示する。古い共有状態は接続待ちへ戻し、最新の成功表示として使わない。

手順図は現行の行順と実UI見出しに合わせる。「2本指を1回」の回数だけで誘導せず、「▶ 開口方向を調整」を確認してから決定する。8手順図・開口方向専用図・docs/28を一緒に更新し、現行手順の入口を一本にする。サイズ変更は同ドックのmm入力で行い、手操作を必須にしない。

## 4. 実装単位と完了条件

### A. 接続処理と試験占有の切分け（R-03/04/08、最優先）

対象：`CStampModule.py` の_CommandServer、`session_client.py`、`ui_bridge.py`、試験スクリプト。

1. 稼働版とソース版を特定し、ソケット識別・接続世代・dropの発生順・応答時間・GUI処理時間をメタデータだけで記録する。
2. ソケット集合からの取り外しをdisconnectより前に完了し、drop/close/replaceを二重呼出し可能にする。古いソケットの遅延dropで新しい接続を停止させない。最後の有効接続喪失では停止・凍結を維持する。
3. MRML更新をまとめ、必要な再描画だけを要求する。ステータス照会と動作命令の応答待ちを区別し、詰まりの場所を計測する。
4. 実Slicer試験の一括同期ループを、Qtイベントを塞がない時間指定の段階実行へ変更する。中断・終了で試験入力を止め、状態を記録して復元する。
5. 通常カメラ経路と画像再生を混在させない試験モードを用意する。入力元は切替時に停止し、同時に二つの認識入力から編集しない。接続は1本。試験解除後も自動受付しない。

完了条件：接続置換・重複drop・遅延drop・中断で例外なし。通常接続と段階画像再生で意図しないタイムアウト／凍結なし。意図的切断では停止・凍結、再接続のみで編集再開なし。TTL・前面・版・重複抑止を緩めて合格させない。単にタイムアウト秒数を増やす修正で終わらせない。

### B. 開始入力と連続操作を分離（R-05）

対象：`op_controller.py`、保持・ラッチ処理、固定ドック。

開始用OPEN_PALMはarmだけに使用し、開始後に手を下げるまで連続操作を抑止する。受付開始ボタンからの開始も同じ準備状態へ入れる。認識喪失・モード変更・編集再開時に前フレームの座標を引き継がず基準点を取り直す。手を戻した最初の有効フレームは基準設定だけに使う。デッドゾーンは距離と時間を計測して決め、開始時の揺れで入力を出さない。

完了条件：旧モードがview/rotate/tiltの各場合に、開始・保持・手下げ・再提示だけではC・視点の座標と角度が不変。モード選択後の意図した移動でのみ連続命令が出る。停止・凍結・不明形・複数手では編集命令0。

### C. モードと無作用理由を常時表示（R-01/07）

対象：`unified_hand_panel.py`、`ui_bridge.py`、`hand_menu.py`、`op_controller.py`。

第3節の表示を実装する。TWO認識時に仮Cが存在すれば「仮配置済み。親指で編集」と示す。照準無効・保持不足・切替待ち・停止・前面外・凍結・通信失敗を区別する。前面化が必要な場合は同じSlicer画面で回復できる導線と理由を表示し、別カメラ窓を前面にする手順を復活させない。モード表示は選択行と独立させる。

完了条件：rotate/tiltを実サーバー状態と照合し表示一致。成功前に有効モードへ切り替わらない。選択・拒否・再接続で青い▶と実選択が一致。仮CありのTWOで追加配置・取消・確定0。案内が現在状態と矛盾しない。

### D. Cの方向を隠さず確認できる表示（R-02）

対象：`CStampModule.py` の仮C表示、固定ドックの方向プレビュー。

実位置・実寸・配置面・角度は保持したまま、同じドックに「C方向プレビュー」を追加する。仮Cの実テンプレートと実角度から面内のC全体、中心、開口方向を描き、直径mmと角度を表示する。「方向確認用・配置面を正面から見た図」と明記し、3D画面上の位置表示と取り違えない。閉じた円の記号でCの開口を代用しない。

3D上のCはラベルや制御点で切れ目が隠れない表示へ整理する。前景モデルに隠れる部分を描画補助で示す場合、隠れている部分と実際に見えている部分を区別する。深度表示や浮かせ描画の可否はレンダラー検証後に決める。検証前の見た目だけを理由にアンカーを外側へ移動したり、面・10mmの実寸を変更したりしない。カメラ正対は確認用の任意操作とし、自動で全体視点を変更しない。

完了条件：正面・斜め・側面・曲率が強い面でプレビューの切れ目と実角度が一致し、3D上の遮蔽があっても方向を確認できる。表示の切替だけで中心・法線・寸法・版・台帳が変わらない。元のモデル／確定済みCを変更しない。

### E. 手形の混同と切替途中の認識（R-06）

対象：`gesture_fsm.py`、`hand_landmarker.py`、ゲート・ラッチ。

グー／親指／つまみの判定を、親指・人差し指の距離だけでなく関節状態と掌に対する配置で切分ける。手の縮尺・傾きに依存するy比較を評価し、必要な場合は関節角度や手の局所軸を併用する。判定を緩める前に、誤った取消・メニュー選択・ズームが起きないことを確認する。明確な形へ無理に丸めず、曖昧な形はUNKNOWNで無作用にする。

保持中の単発揺れと独立した次操作を区別し、1本→2本、2本→3本、グー→親指、開いた手→親指の遷移を試験する。握ったグーと実際につまんだ手の両方を使う。合成イラストへの閾値合わせだけで変更しない。実手確認では映像を保存せず、結果・メタデータだけを残す。

完了条件：明確な手形の指定試験で正しい判定と操作が成立し、切替途中・単発誤認識では離散命令0。不明時の操作0。グーでメニュー内の戻る／閉じるが成立し、取消の意図がない経路で仮Cを捨てない。現行メニュー外FIST取消の仕様は表示・確認と合わせて検収し、無断で意味を変えない。

### F. 正常経路・失敗経路を実ツールで再検収（R-08、全項目）

対象：実試験ハーネス、docs/26/27/28/32、本書、PROJECT_STATUS。

合成画像のモデル推定、記録用接続、実ローカルdispatch、実TCP、実Pixelの手入力を別試験として実施する。実TCP試験では版・req・seq・TTL・前面条件・再接続を通す。別の診断接続で実認識アプリの接続を奪わない。試験用モデルと保存先を明示し、既存仮Cは試験後に方向・カメラを復元、更新版を過去へ戻さない。保存試験が必要な場合は非臨床の隔離シーンと試験用台帳を使う。
