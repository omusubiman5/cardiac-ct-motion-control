# 🤟復帰・画面内ジェスチャー移行 実装計画

## 承認根拠・対象

本人原文：「パーで認識→画面外にして→再度操作 が面倒過ぎる」「iloveyouで復帰させたらすぐに作業に移れないか？」「実装計画書MDを作って実装して。その後、実装報告書MDを作って。」

対象は非臨床Pixel／MediaPipe標準分類→通常認識器→署名済みSlicerデモ。要件正本docs/03のFR-001（明示開始）、FR-013（マウス代替）、SR-003／008（異常停止・自然再開禁止）、SR-009（確定独立）を維持する。既存C台帳・モデルは変更しない。

## 操作仕様

1. 停止中：標準ILoveYou（親指・人差し指・小指）を既存の開始保持時間1.5秒、既存品質条件で認識するとarmを1回送る。パーは開始に使わず視点回転専用へ戻す。
2. 開始直後：🤟保持、UNKNOWN、手なし、複数手では動かさない。
3. カメラ内でパー／人差し指／つまみへ変え、既存離散保持時間0.35秒安定したら準備を解除。解除フレームでは動かさず、次フレームから位置を基準化して通常操作する。画面外への手下げは不要。
4. 復帰からの最初の手形として、確定・取消・スタンプ・メニュー用手形を受け付けない。作業用3形への安定移行を先に必要とする。
5. 凍結中の仮Cはそのまま保護し、armだけで編集再開・確定をしない。既存の明示的な仮C編集再開を残す。再接続のみの自動開始はしない。
6. 通常マウスの受付開始も同じ画面内の作業用手形へ移行できる。既存マウス停止・手への引継ぎ・session再接続修正を維持する。

## 反証可能な仮説と試験

H1：復帰専用形と連続操作形を分離すれば、手を画面外へ出さずに、開始形による誤回転を防げる。

反証条件：パーだけで開始する、🤟保持で視点／Cが動く、不確かな切替で準備解除される、解除瞬間に座標差分が跳ぶ、確定／取消が発行される、凍結Cが自動再開される。

自己検証：標準ILoveYouの高／低スコア・複数手、保持と再送防止、3形移行、途中UNKNOWNで安定時間リセット、解除時命令0、次フレーム基準化とその後の移動、準備中の離散命令0、セッション失効・凍結保護の回帰。既存試験が旧パー開始要件を固定している部分は本人変更原文に従って更新し、異常停止試験は削らない。

実アプリ検証：配布物・実ロードhashを照合した署名済み版で起動。メタデータだけを記録し、実Pixel🤟→arm受理→作業形安定→手下げなしの操作命令→Slicerカメラ変更・描画を確認する。合成入力の自己検証と実手検収を区別し、実手未取得なら明記する。

## 実装順序と変更予算

各段階は1ファイルずつ変更・局所試験する。独立した1変更テーマだが、認識enum、標準カテゴリ対応、操作状態機械、利用者向け文言は境界が異なり単一ファイルでは成立しない。最後に同一版として配布する。

1. gesture_fsm.py：ILOVEYOU形の識別子だけ追加。
2. standard_gesture.py：標準ILoveYouを既存スコア閾値で対応。低品質時UNKNOWN。
3. op_controller.py：開始形変更・安定移行の準備処理。連続操作の差分基準をリセット。
4. ui_bridge.py／Slicerパネル／認識表示：開始案内と手下げ案内の更新（ファイルごと）。
5. 試験・要件正本・現行操作表・報告書を整合させる。無関係なジェスチャー割当は変更しない。
6. 実カメラ・実Slicer観測でruntimeを再構成、署名配布・正式起動・既存入口更新。稼働中payloadの書換え・署名ゲート迂回なし。

依存関係追加0、モデル追加0、患者データ0、治療操作0。保存済みC台帳はhashで保全。仮Cや未保存の変更を観測した場合は再起動前に再評価する。旧署名版は保持し、必要なら正式rollback入口で戻す。
