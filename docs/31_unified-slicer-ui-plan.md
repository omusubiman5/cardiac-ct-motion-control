# Slicer内へ操作UIを集約する実装計画

2026-10-10。本人原文「カメラを含めて３つのパネル」「どれも最前に出すなんて」「UI改善がUXに繋がる」「実装計画書MDを作って、実装して」を対象とする。docs/03のFR-001（明示開始）、FR-003（状態区別）、FR-005/013（通常操作共存）、許可対象前面の共通安全ゲートを維持する。既存docs/23の操作機能を削除せず、表示・操作場所を変更する。

## 完了条件

- Slicerに固定した一つのドックへ受付状態、現在手形、保持時間、メニュー一覧、拒否理由を表示する。別アプリの前面化や常時最前面窓を必要としない。
- カメラは既定非表示。必要時だけ同じドックのプレビューを表示し、画像はメモリー内だけで転送、保存・外部送信しない。
- 認識プロセスはバックグラウンド化し、OpenCVカメラ窓・Tk最前面HUDを作らない。Slicerの設定・メニューを操作しても同一プロセス内にとどまる。
- C直径設定は同じドックに展開する。10mm初期設定、次のC／現在仮Cへの適用の区別、確定済みC不変を維持する。
- 明示開始・停止ボタンを同じドックに提供し、ハンド開始も維持する。メニューのマウス代替は手入力と同じ認識側コントローラーから型付きプロトコルへ送る。C確定は独立確認と版照合を維持する。
- 従来の詳細マウス操作は削除せず、同じドックの「詳細マウス操作」タブへ収容する。独立窓へ戻らなくても通常操作へ切り替えられる。
- 認識停止・切断・古い状態は受付中に見せない。前面安全ゲートを削除しない。他アプリへ移ったらモデル変更を拒否する。

## 実装順序と対象

1. 標準ライブラリーによるWindows名前付き共有メモリーを導入。状態／オプションカメラとUI要求を別領域に分け、一方向ごとに単一書込元、世代番号・チェックサム・最大容量で不完全読込を拒否する。ディスクファイルや第二のSlicerコマンド接続は作らない。
2. 認識app.pyから現在の階層メニューと診断状態を共有する。Slicerモードだけ独立窓を廃止する。UI要求は許可された開始・停止・メニュー開閉／移動／選択へ限定し、期限・ID重複を検査する。
3. Slicer内Qtドックを作成。共有状態を期限付き表示し、プレビューは明示表示時のみ画像を取得する。サイズ設定は既存UIをドック内に埋め込む。
4. 起動時にドックを設置する。既存稼働SlicerではUIのみ追加し、シーン・仮C・保存台帳を維持する。認識アプリのみ再起動する。
5. 自己検証で共有メモリー破損／古い要求／二重実行／メニュー動作を確認する。実Slicerで単一ドック・サイズ展開・開始／停止・別窓不在を検収する。カメラ画像を証跡へ保存しない。

## 検収の区別

自己検証、実Qt表示とマウス操作、本人の実手操作を別々に記録する。UI統合を臨床使用可能・全C保存機能合格とはしない。docs/27の既知不合格は残す。実装結果・未実施事項は本書末尾とPROJECT_STATUS.mdへ追記する。

## 実装結果（2026-10-10）

実装・稼働反映済み。認識側は `ui_bridge.py` のWindows名前付き共有メモリーで状態・メニューと、明示表示した場合のみ320×240のJPEGプレビューを渡す。撮影ファイルを作らず、TCPコマンド接続は従来の1本を維持する。UI要求は2秒の期限・許可リスト・ID重複拒否と1件ずつの応答確認で処理する。読み取り途中や破損した共有状態は採用しない。

`unified_hand_panel.py` のSlicer固定ドックへ一覧・状態・開始／停止・手形・保持時間・カメラ・サイズ設定を収容。メニュー選択は▶と青い行で示し、一覧をクリックしただけで内部選択が変わったように見せない。長い一覧と小画面はスクロール可能。Slicerモードのapp.pyは独立OpenCV窓・Tk HUDを作らない。従来の詳細マウスUIは同じドックの別タブへ収容した。Slicerの診断ログとコンソールは通常表示から畳んだ。

サイズ設定は既存のダイアログ内容をWidgetとしてドック内に埋め込む。「閉じる」はその設定部分だけを閉じる。直径10mmを保持し、次のCだけ／現在仮Cへの明示適用の契約を維持。認識再接続で仮Cは凍結するため、自動解除しない。SlicerのUIハートビートが10秒失われると認識プロセスは終了する。受付状態と変更操作の前面安全ゲートは維持した。
