## 1. 目的と正本

操作者がマウス・キーボードに触れず、視点操作、Cの配置・編集・確定・取消、計画、訂正、復旧まで行えるかを実画面と保存データで検証する。通常操作は故障時の代替として別に試験する。代替操作で成功しても手操作の合格に振り替えない。

要求の正本は[システム要求](03_system-requirements.md)、安全境界は[README](../README.md)、試験方針は[非臨床検証計画](05_validation-plan.md)。[実装報告](21_implementation-report.md)の第3版・追加分2を現状報告として読み、[実装計画第2版](23_hand-motion-completion-plan.md)のH-01〜12、X-01〜08へ本書の実施手順を結び付ける。原要求や実装計画を置き換える別の要件正本は作らない。

実装報告の後半は過去版を含む。131件・66件の単体試験とSlicer E2Eの成功は報告書記載の既存証拠であり、今回の再実行結果でも、実手試験の結果でもない。`ok:true`だけで原要求の意味的適合を判定しない。

患者、臨床機器、治療パラメーターは対象外。合成形状または由来を確認した非患者デモだけを使う。カメラ映像、顔、CT/DICOM、音声、手術動画を記録・送信しない。映像録画による遅延測定は行わない。

## 3. 役割・開始準備（G-00）

- 操作者：手だけで指定操作を行い、意図した動きを宣言する。操作中のキーボード／マウス補助は介入として記録する。
- 試験担当：開始前準備、読み取り専用の観測、台帳比較、意図した故障注入、緊急停止を担当する。操作者の代わりにコマンドを送った結果は実手合格にしない。
- 開発担当：阻害事項の修正、版固定、ログ・描画・保存の観測点を準備する。試験中の調整を同じ版の結果へ混ぜない。

開始前チェック：

1. 試験IDを`FIELD-YYYYMMDD-NN`として採番し、参加者は匿名の区分で記録。対象コード、Python/依存、Slicer/Windows、カメラ、認識モデル、設定、デモモデル、Cテンプレートの版とSHA-256を固定する。
2. 非患者データであること、モデルの座標系・単位・表面・変換を確認する。由来不明のデモは使わず合成形状へ替える。
3. 試験専用の台帳・計画ファイル・ログを登録する。現行既定の`artifacts/cstamp/events.jsonl`や既存`plans.jsonl`、既存結果を流用・削除しない。試験IDごとの保存先に切り替えられない場合は確定・計画変更試験を開始しない。
4. 既存プロセス・ポートの所有者を確認し、二重起動を避ける。Slicer起動は既存手順`start_server_session.py`を参照するが、同スクリプトのデモ・保存先・固定ログを点検してから行う。既存セッションの状態を推測しない。
5. 認識アプリは`run.ps1 -CameraIndex <確認済み番号> -SlicerConnect`の経路を使用。マウス出力の`-EnableInput`は付けない。カメラ番号1という過去値を現場で無確認に固定しない。署名・実行ポリシーで拒否された場合は回避せず担当に戻す。
6. Slicerが前面、受付DISABLED、DRAFTなし、登録保存先、対象表面、手数・認識状態・ゲート理由・モード・レイヤー・受理／保存結果を観測できることを確認する。readyファイルやTCP接続だけで準備完了にしない。
7. 台帳件数とハッシュを採取。件数は総JSON行数だけでなく、PLANNED、PERFORMED、取消／訂正／理由監査を別集計する。
8. 通常マウス・助手による停止経路を試験担当が準備する。未接続フットスイッチは「利用可能」と記載しない。手による停止だけに緊急停止を依存しない。
9. 計算許容誤差と比較項目をX-05の形式決定に合わせて固定する。未決なら数値再現性は測定のみ、AC-008/011/016/018の合格を保留する。

試験開始前の準備ではマウス利用可。開始後の主操作に介入が必要になったら、そのケースは中断または手操作未達と記録する。故障注入・プロセス再起動は担当の操作として明示し、操作者の操作成功と混同しない。

## 4. 現在の手操作早見表

以下は原要求の固定仕様ではなく、今回照合したコード上の試作割当て。起動時の設定値と照合して使う。通常保持の既定0.35秒、開始保持の既定1.5秒は実装値であり、性能合格基準ではない。

| 場面 | 手の操作 | 画面で確認する作用 |
|---|---|---|
| 無効時 | 開いた手を1.5秒保持 | ARM受理、VIEW。開始しただけでモデルが動かない |
| VIEW | 開いた手を左右／上下へ移動 | カメラ回転 |
| VIEW | 人差し指を立てて移動 | パン |
| VIEW | ピンチして上下へ移動 | 上で拡大、下で縮小。解放後停止 |
| メニューを開く | 親指だけを立てる | メニューと現在の選択項目 |
| メニュー内 | 2指を提示→解放、繰り返す | 1回につき次項目1つ。保持し続けて送らない |
| メニュー内 | 3指を提示 | 選択項目を実行。DRAFT確定とメニュー実行を文脈で区別 |
| メニュー内 | 拳 | メニューを閉じる（親指の再検出では閉じない） |

## 5. 実施順と中止条件

初回はG-00（準備）→H-01の開始停止→H-11の保持／誤確定防止→H-10の停止復旧→H-02の基本編集、の順。安全上の不具合があれば以後の確定試験を停止する。その後H-03、H-04〜09、H-12、X試験、環境・性能試験へ進む。既知の実施不可部分は飛ばした理由を残し、全機能合格とはしない。

各基本ケースは練習1回を別記し、記録対象3回を初回の探索量とする。性能の統計的合格や臨床合格を意味しない。不合格が1回でも出たら修正前の結果を残し、修正後は新しい試験ID・版で当該ケースと影響ケースを再実施する。

直ちに止める条件：意図しない確定／取消監査、同一DRAFTの重複保存、対象外アプリへの作用、認識喪失後の継続移動／自動再開、元モデルや既存記録の改変、禁止データ保存・外部送信、操作不能・強い疲労。手を引いて停止しなければ試験担当が通常手段で入力プロセスを停止する。モデル編集や台帳削除で証拠を消さない。

保存失敗は試験用の書込失敗注入点で再現する。実ディスクを満杯にしたり、共有台帳の権限を書き換えたりしない。通信断も試験クライアントだけを対象とし、PC全体のネットワークを切らない。

## 8. 環境・操作性・性能の測定

段階Aは卓上基準条件、Bは一要因ずつの環境変更、Cは安全ケース合格後の模擬作業とする。照明（明るさ・方向・逆光）、手袋色／材質、袖、手の距離・角度、左右手、遮蔽物、第二人物の手、反射物を記録する。比較条件ではモデル・設定・操作者を固定し、変更要因だけ替える。人物の識別能力を片手検出から推定しない。

初回探索の割当て：基準条件で各手形を10試行、各環境条件で主要操作を5試行、無操作監視を30分。操作者は確保できた人数を匿名区分で記録し、1名なら1名の探索結果と明記する。これは臨床合格を証明する標本数ではない。疲労時は休憩し、連続10分程度を区切りとして実時間を記録する。

- 成功率：意図した手形の認識成功／試行数と、意図したSlicer操作の成立／試行数を別々に集計。見逃し・誤分類・拒否・再試行を残す。
- 誤作動率：意図しない**受理コマンド数**／実観測時間（時間単位）。送信数も別集計。30分ゼロ件を長期安全の証明としない。無操作中と操作中を分ける。
- 遅延：手の開始→分類→受理→実画面反映→保存の時点を区別。時刻源を同期し、p50/p95/最大・件数・欠測を記録。現行dispatch p50/p95は受付処理だけで、端から端の値ではない。描画計測がなければ欠測とする。目視ストップウォッチは粗い所要時間に限定する。
- 回転操作性：固定された非患者モデルの目印を指定視点へ合わせる。逆方向への動き、行き過ぎ、持ち直し、モード誤認、完了時間、利用者の予測しやすさ・疲労を記録。旧設定との比較は設定版を分ける。パン・ズームも同じ課題で回帰確認する。
- 復旧：故障検出→停止、故障解除→明示再開、通常操作へ引継ぎ→最初の有効操作、の時間を分ける。

定性的な安全不変条件は原要求で判定する。遅延上限、認識率、誤作動率など未承認の数値は「測定済み・合否保留」とし、docs/05・FR-023・PR-001〜004の合意手順へ戻す。

## 9. 記録票と完了判定

結果は既存`evidence/`配下に試験IDごとに保存し、正本の要求追跡表へリンクする。今回作るのは計画だけであり、空の試験結果を合格証跡として登録しない。

```text
試験ID／日時（JST）／担当・操作者区分：
対象版・ファイルハッシュ／構成・モデル・設定版：
H/XケースID・枝番／原要求・AC：
前提・環境・台帳件数／実際に行った手順：
操作者の意図／認識／送信／受理／実画面観測／保存結果：
DRAFT ID・版／event ID・record_type／前後ハッシュ：
期待結果／実結果／数値・時刻源・欠測：
マウス・助手・合成入力の介入と理由：
証拠パス／PASS・FAIL・BLOCKED・NOT RUN・測定のみ：
阻害ID／不具合ID／修正担当・対象版／再試験ID：
利用者確認：済・未（確認した範囲を記載）
```

PASSはそのケースの前提・全期待結果・必要な証拠が揃った場合だけ。観測不能はPASSにしない。BLOCKEDは未実装または準備不足、FAILは実施して要求に反した場合、NOT RUNは未実施。合格した反復だけを抜き出さない。ケースを途中で分割した場合も元の全ケース判定を残す。

機能完了にはH全件とAC全件の必要な実手・代替・技術試験、利用者確認が必要。B項目が残れば該当範囲未達。実手成功と性能合格、署名・配布適合、臨床承認は別判定とする。報告は`docs/21`の現行節と`PROJECT_STATUS.md`へ追記し、過去の結果を改変しない。
