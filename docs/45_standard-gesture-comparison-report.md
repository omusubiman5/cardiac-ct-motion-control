## 2026-10-12 Cメニューから戻れない訴えへの是正

本人原文「Cメニューに入ってから戻れない」「グーは認識するけど、メニューが変わらない」。調査時の通常ログにはtransport: timed out、その後status成功／armed=Falseがあり、受付停止中だった。ユーザーの全操作時刻とログを対応づけてはおらず、全事象の単一原因と断定しない。

コードでは停止中にローカルメニューを閉じるがmenu_openミラーを残していた。さらにui_bridgeは閉状態でもdraftがあるとEDIT一覧を表示するため、閉じた状態とC編集メニュー内の見分けがつかなかった。menu_openを同期して閉じ、閉状態はmainの未選択一覧へ変更。停止中の理由に「受付停止中：開いた片手を1.5秒保持して再開」を明示した。グーの認識閾値は変更せず、停止中に操作を通す変更もしていない。

実OperationControllerと共有状態publisherの自己検証を追加。初回は診断器のlast_id初期化漏れで失敗し修正後、全2,235 PASS（menu-return-tests.txt）。修正版通常認識の共有状態でconnected=True、armed=False、opened=False、page=main、selected=-1、draft=Trueと停止理由を確認（menu-return-live-state.json）。これは発行状態の確認で、実画面ピクセルや本人の再操作の合格ではない。Slicer追加起動なし、開始・確定・取消を送信していない。

runtime hash `ec8581736868050d5316721e228ebfbba102a39818a5bd50f9e7d83a962cbbf3`。タイムアウト自体の発生原因は今回未解消。再開後のC編集→グー→主メニュー→グー→閉じるは本人の再確認が必要。
