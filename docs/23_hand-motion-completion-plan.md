## 達成すること

2026-10-10本人追加：C中心線の直径をmmで表示・変更するサイズ設定を追加し、基準値は直径10mmとする。「ここはハンドモーションでする必要なし」により、サイズ設定はマウスの数値入力・適用ボタンを採用する。現在仮Cへの変更は明示選択し、確定済みCを変更しない。仕様・実検証はdocs/30_c-stamp-size-settings.mdに結び付ける。

操作者がマウスやキーボードに触れず、心臓3Dモデルの視点変更、Cスタンプの照準・仮配置・位置調整・方向調整・明示確定・取消を実行できる状態を作る。計画作成と実績記録の切替、次の予定参照、保存・再表示も同じ操作体系へ接続する。

今回のユーザー訂正「マウスが使えるならハンドモーションいらない」を設計の前提とする。マウス操作の成立だけで目的達成と判断しない。通常マウス・助手・フットスイッチはREADMEの安全原則に従う代替手段であり、ハンドモーションの主操作経路に必須の手順を残さない。準備担当によるソフトウェア起動、デモシーン・保存先の設定と、操作者による使用中の操作を区別する。

「Cの焼き印」は画面上のCスタンプ操作を意味する。実機の焼灼、治療機器制御、治療位置の自動決定へ拡張しない。

## 利用者の操作の流れ

1. 準備担当がデモシーン、許可表面、保存先、カメラを設定して起動する。起動時は操作無効。
2. 操作者が手による明示開始操作を行い、受付中の表示を確認する。
3. 視点操作モードで回転・パン・ズームを行う。
4. 照準モードへ切り替え、モデル表面上の配置位置を選ぶ。配置不可ならスタンプしない。
5. スタンプ操作でCを仮配置する。この段階で確定ログを作らない。
6. 位置調整・開口方向・傾斜を必要に応じて調整する。カメラ操作とC操作は別モードで扱う。
7. 独立した確定操作で1件を保存する。成功通知を確認して次のCへ進む。取消では現在の仮配置だけを捨てる。
8. 手による終了操作で無効化する。必要時は確定点の選択・C再表示・計画対実績表示を行う。

計画作成時はPLANNED、実績記録時はPERFORMEDを常時表示する。DRAFTが残る間のレイヤー変更は拒否し、確定先が途中で変わらないようにする。

## 操作モードとジェスチャーの設計

操作一覧図: [実装済み操作と追加ジェスチャー候補](images/hand-gesture-candidates-2026-10-09.png)。追加候補・編集操作は未実装。図の照準・位置・開口方向・傾斜の割当ても試作案であり、原要求の確定済み割当てではない。

同じ手の移動が、カメラとCスタンプを同時に動かさないようにする。受付状態と編集状態は別々に表示する。

| 操作モード | 手の移動が変更するもの | 禁止する作用 |
|---|---|---|
| VIEW | カメラの回転・パン・ズーム | Cの位置・形状、台帳変更 |
| AIM | 画面上の照準と表面交点 | 自動スタンプ・自動確定 |
| MOVE_DRAFT | 仮配置Cのアンカー位置 | カメラ回転、既存確定イベント変更 |
| ROTATE_OPENING | アンカーを固定した面内方向 | アンカー移動、傾斜の同時変更 |
| TILT_PLANE | アンカーを固定した配置面方向 | 面内回転の混入、確定 |
| REVIEW | 予定・確定点の選択と読み取り専用表示 | 元データ・既存確定イベントの編集 |

モード選択、受付開始・停止、確定・取消も手で操作できる、画面上の小さな操作メニューを設ける。準備用ボタンだけに機能を置かない。メニュー表示中はモデルの連続操作を停止し、選択先・保持進捗・成立／拒否理由を表示する。

具体的な追加ジェスチャーは実装時の試作案とし、原要求の承認済み割当てとは扱わない。候補は、既存3形状に加えて、2指、3指、握りこぶし、親指のみを独立分類する方式。例えば「2指＝スタンプ」「3指＝確定」「握りこぶし＝取消」「親指のみ＝モードメニュー」を比較する。開始操作は無効状態でも判定する専用経路に置き、開始したフレームから即操作を出さない。

- スタンプと確定は別形状・別操作にする。確定をピンチ解放やモード切替の副作用にしない。
- 離散操作は安定保持、立上り、解放後の再受付を組み合わせる。保持時間・信頼度・再受付時間は設定として版管理し、実測で調整する。
- メニュー選択だけでは確定ログを作らない。COMMIT_DRAFTは専用の明示操作だけで発行する。
- 認識不能、複数手、通信断、対象喪失は連続出力停止。DRAFTは取消せず凍結する。認識復帰だけで編集・確定を再開しない。
- 「片手検出＝権限者本人」と扱わない。人物識別の課題は残し、制御した単一操作者の非臨床試験で評価する。
- 操作イラストは実装した割当てに更新する。説明図だけで未実装ジェスチャーを使えると案内しない。

## 入力とSlicerを結ぶ共通契約

`slicer_bridge.py`とSlicer側受付を、視点3操作から型付き操作の許可リストへ拡張する。任意Python、キー列、シェル、任意ノード編集を送るAPIは設けない。

| 操作群 | コマンド案 | 受理条件・作用 |
|---|---|---|
| 受付 | ARM、DISARM、RESUME_DRAFT | 明示開始・停止・凍結解除。再接続による自動開始禁止 |
| モード | SELECT_MODE、SELECT_LAYER | 状態に対して許可されたモードだけ。DRAFT中のレイヤー変更禁止 |
| 視点 | VIEW_ROTATE、VIEW_PAN、SMOOTH_ZOOM | カメラだけを変更。原モデル・Cデータ不変 |
| 基準視点 | RESET_VIEW（用途整合の確認対象） | docs/01とdocs/10の候補操作。FR-002の現行許可列挙との整合を確認し、採否を記録。採用時は事前登録カメラ姿勢だけを復元 |
| 照準 | AIM_SURFACE | 指の画像座標を正規化して許可3Dビューの座標へ写像し、許可表面の交点を更新 |
| 仮配置 | STAMP_DRAFT | 有効交点、DRAFTなし、明示立上り。表面・照準の一致を確認 |
| 位置調整 | MOVE_DRAFT | 同じdraft_id、許可表面上の有効交点だけ。確定ログを増やさない |
| 方向 | ROTATE_OPENING、TILT_PLANE、REVERSE_PATH、RESET_DIRECTION | 同じdraft_idに限定。アンカー不変。各パラメーターを分離 |
| 確定・取消 | COMMIT_DRAFT、CANCEL_DRAFT | draft_idと要求IDで重複抑止。成功時だけ画面・台帳を更新 |
| 計画 | LOAD_PLAN、SELECT_PLAN_ITEM、SKIP_PLAN、REORDER_PLAN | 事前登録計画だけ。理由・時刻を記録し、承認済み計画を上書きしない |
| レビュー・訂正 | SELECT_EVENT、SHOW_C、BEGIN_CORRECTION | 確定点から読み取り専用再構成。訂正は新規イベントで関連付け |

保存先や計画ファイルは準備段階で登録した識別子から選ぶ。手入力の通信から任意ファイルパスを指定しない。

通信には版、セッションID、要求ID、連番、draft_id、操作時刻、有効期限を持たせ、型違い・範囲外・古い操作・別セッション・状態不一致を拒否する。切断前に生成された確定要求を復旧後に自動再送しない。保存済み要求の結果照会と、新しい確定操作を区別する。

Slicerから受理／拒否理由、現在状態、draft_id、event_id、処理結果を返す。現在の「sent」は輸送送信だけを表すため、画面には「送信」「Slicer受理」「記録保存」を区別して表示する。同じ入力で複数確定しないことを、再送・遅延・切断を含めて検証する。

### 配置位置の変更方法

MOVE_DRAFTは、画面照準と許可表面の交点を使ってアンカーを移す。表面外のときは直前の安全な仮配置を維持する。移動だけでは開口角・進行方向を変えない。法線が異なる表面へ移るときの配置面更新と方向の引継ぎ規則を決定的に実装し、更新前後の基底・角度を試験する。台帳への正式記録は確定時だけ行う。

### 回転の改善方法

まず指の形が回転中に別分類へ落ちる問題、手を動かした量と回転角の対応、回転軸、姿勢の急変をログで切り分ける。カメラの上方向を維持する方式と、視点に追従する方式を非臨床デモで比較する。回転専用の感度・不感帯・速度上限を設け、パン・ズーム設定と分離する。分類の安定化で認識喪失時停止が遅れるようにはしない。数値設定は利用者の実操作評価で決める。

### 前面ウィンドウとプレビューの整合

原要求のTASK共通安全ゲートは、許可対象ビューが前面にあることを求める。現在は外部カメラ画面へフォーカスしてSpaceを押す構成であり、単なるloopback接続はこの条件の証明にならない。Slicer内に状態・操作ガイドを統合し、操作者が外部カメラ画面へ切り替えず操作できる構成にする。別アプリが前面に出たら視点・C編集とも停止する。カメラ映像を表示する場合もメモリ上だけで扱い、保存しない。

## 第2版：実装契約と追加受入仕様

本節は上記の概略を具体化する必須作業である。試験は全て計画段階・未実施。表内の対応付けを「要求合格」と読まない。担当は実装担当、試験担当、利用者確認者を実施開始時に記名する。

### 表示済みDRAFTの原子的確定（ONI-001、単位2・5・6）

- Slicerの単一ディスパッチで編集を直列化し、`draft_id`に加え単調増加する`draft_revision`を付ける。座標・方向・形状・対象モデル／テンプレート／レイヤーの版を含む不変スナップショットとハッシュを生成する。
- 描画要求の発行だけで表示済みとしない。対応スナップショットの描画完了をSlicer側で確認して`displayed_revision`を公開し、内部版と一致する間だけ確定可能表示にする。描画完了を検証できない構成では確定を拒否する。
- 確定要求は操作者に提示した`draft_id`・表示済み版・ハッシュを束縛する。確定の安定保持開始から成立までに編集・表示版が変わればその保持を無効にし、解放後に再確認を要求する。未反映編集や版不一致がある間は確定しない。
- 確定受理時に版を比較し、スナップショットをロックする。保存中の手・マウス編集は拒否し、後から見えない編集を適用しない。保存成功後だけCOMMITTEDへ遷移する。保存失敗では同じDRAFTを保持して未確定を表示する。
- 要求IDの重複排除と版一致は別々に検証する。同じDRAFTの異なる要求IDによる重複確定も防ぐ。保存成功・応答喪失では結果照会のみ行い、再確定しない。再起動後も永続台帳から照会できるよう、データ書込と確定索引の整合・途中終了時回復を単位6に含める。
- 試験X-01：編集遅延、描画遅延、順序逆転、編集直後の確定、確定保持中の更新、手とマウスの競合、保存途中終了、応答消失を各々注入する。許される結果は「最後に表示確認した同一版を1件保存」または「確定拒否・0件」。表示版・内部版・要求版・保存ハッシュを非映像ログで突合する。自己検証と実Slicer観測を分ける。

### 代替マウスの完成と入力の所有権（ONI-002、単位3・5）

主経路は手だけで完結させる。代替マウスには表面ドラッグによるMOVE_DRAFT、連続スライダー／ドラッグによるTILT_PLANE、開口回転・反転・リセット、仮配置・確定・取消を設け、手と同じディスパッチ・版検査へ接続する。ホイールも共通SMOOTH_ZOOMへ変換する。

手入力のARMと通常操作の受付を分離する。手がDISABLED、遮蔽、カメラ断でも、対象ビュー・シーン・モデル・保存系等の共通安全条件が成立すれば、明示的なマウス引継ぎで通常操作を使える。引継ぎ時は手を停止して未処理の手要求を無効化し、最後の表示済みDRAFTを引き継ぐ。通信断でもSlicer内の通常UI経路を維持する。共通データ破損や対象不一致をマウスで回避してはならない。

試験X-02：手無効・遮蔽・カメラ断・手通信断を別ケースとして、マウスで配置→移動→連続傾斜→開口回転→確定、および取消を行う。手操作の同じ列とAC-007を比較する。独立採番ID・時刻は対応表で照合し、入力手段以外の意味的データ差を隠す正規化はしない。引継ぎ後の遅延手要求は0作用。手への復帰は明示開始と解放を必要とする。
